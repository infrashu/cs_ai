# Legaseed CS データ参照ルール

## 目的
定期MTG準備に必要な情報を、許可されたデータソースから取得する。
数値・顧客発言・契約情報の根拠を明確にし、正確な分析と提案を行う。

## 1. データソース

### BigQuery
取得する情報：
- 求人PV・応募状況（取得可能な場合）
- 自然応募・スカウト経由の応募
- 選考ステータスと選考進捗
- 面接・内定・内定承諾状況
- 月次・週次の推移

確認事項：
- 対象企業・求人・プロジェクト
- 対象期間と更新日時
- 指標の定義と集計単位
- データの重複や集計対象外のレコード

データセットによって取得できる項目が異なるため、利用可能なテーブルを確認する。

### Googleスプレッドシート
取得する情報：
- 企業カルテ
- 契約プラン・契約期間・契約終了予定日
- 採用目標・採用枠
- CS担当者
- 最終顧客連絡日・最終CS連絡日
- 顧客の管理状態・対応履歴

企業カルテは最新状況の確認先として優先する。
更新タイミングの異なる情報は混同しない。

### Google Drive / Google Docs
取得する情報：
- 企業別フォルダのMTG議事録
- 顧客の理想・採用目的
- 過去の課題と提案内容
- 顧客の発言
- 合意事項と未完了の宿題
- 今後の予定

直近の議事録を優先しつつ、初回MTGや重要な意思決定の記録も確認する。
ファイル名だけで判断せず、本文を読む。

## 2. 企業の特定
1. 企業カルテやシステム上の企業IDを優先する。
2. 企業名の表記揺れを確認する。
3. 同名・類似名の企業を混同しない。
4. 複数の候補がある場合は確認を求める。
5. データソース間で企業が一致する根拠を確認する。

## 3. 情報取得の順番
1. 対象企業を特定する。
2. 企業カルテから契約・目標・担当者を確認する。
3. BigQueryから応募・選考・採用状況を確認する。
4. Google Driveから過去のMTG議事録を確認する。
5. 過去の約束と未完了事項を整理する。
6. 現状と顧客の理想のギャップを分析する。
7. 顧客ジャーニーと判断ルールに基づいてアジェンダを作成する。

## 4. 数値の取り扱い
- 応募数・面接実施数・内定数・承諾数を区別する。
- 選考中の学生と実施済みの学生を混同しない。
- 集計期間と更新日時を確認する。
- 企業単位と求人・プロジェクト単位を混同しない。
- データの不一致がある場合は原因を確認する。
- 不明な数値を推測で補完しない。

## 5. 顧客の理想と過去の合意事項
議事録から以下を抽出する。

- 顧客が実現したい将来の状態
- 採用目標とその背景
- 顧客が抱えている課題
- 顧客自身の発言
- CSが提案した内容
- 合意済みの施策
- 未完了の宿題
- 次回までの予定

顧客の明示的な発言とAIの仮説を区別する。

## 6. データが取得できない場合
取得できないデータは「未取得」と明記する。
確認できた情報だけで暫定的な準備案を作成する。
アクセス権限のない情報は取得しない。

## 7. データの鮮度
- データの取得日時を記録する。
- 議事録の会議日と更新日を区別する。
- 過去の情報と最新の情報が異なる場合は確認する。
- 契約情報など重要な項目は最新のデータを優先する。

## 8. 情報セキュリティ
- すべてのデータ取得は承認済みの接続先で行う。
- 認証情報・APIキー・顧客データを公開GitHubに保存しない。
- 個人情報の取得は必要最小限にする。
- 閲覧権限と外部への共有権限を区別する。
- 顧客情報を許可なく他社の事例として使用しない。
- 明示的な承認なくシステムのデータを書き換えない。

## 9. 接続設定
具体的なデータベースID、スプレッドシートID、Google DriveフォルダID、認証情報はこの公開ファイルに記載しない。
実際の接続時に、権限管理された設定と利用可能なコネクタを参照する。

このファイルはデータ参照方針を定義するものであり、データソースとの接続自体を完了させるものではない。
