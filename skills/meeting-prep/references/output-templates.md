# Legaseed 定期MTG準備 出力テンプレート

## 基本方針
顧客の理想実現と採用成功に向けて、CS担当者がそのままMTG準備に使える内容を作成する。
単なる数値の報告ではなく、課題の発見・改善提案・合意形成を重視する。

## 1. MTG概要
- 企業名
- MTG予定日時・所要時間
- 利用サービス・契約状況
- 今回のMTGの目的
- 情報の取得日時

## 2. 顧客の理想と目標
- 3〜5年後に実現したい事業・組織の状態
- 今期の採用目標
- 採用によって実現したい成果
- 顧客が重視していること

顧客の発言とAIの仮説を区別する。

## 3. 現状分析
以下のうち取得できた情報を整理する。

| 項目 | 現状 | 目標 | 課題・補足 |
| --- | --- | --- | --- |
| 求人PV | | | |
| 応募数 | | | |
| 面接実施数 | | | |
| 内定数 | | | |
| 内定承諾数 | | | |
| 採用後の活躍状況 | | | |

数字には対象期間・定義・参照元を記載する。
実施済みと進行中の選考を混同しない。

## 4. 過去のMTGからの引き継ぎ
- 顧客の発言や要望
- 前回の合意事項
- CS側の宿題
- 顧客側の宿題
- 未完了事項
- 過去に提案した改善施策

重要事項には議事録の日付を付ける。

## 5. 顧客ジャーニーの現在地
- 現在の段階
- 段階を判断した根拠
- 次へ進む条件
- 条件ごとの達成・未達・不明
- 今回優先する課題

customer-journey.mdを参照する。

## 6. 今回のMTGで実現したいこと
今回のMTGのゴールを1文で示す。
顧客と何を合意できれば成功なのかを明確にする。

## 7. 推奨アジェンダ
優先度の高い最大3テーマを提案する。

| 時間 | テーマ | 確認・質問事項 | 合意したいこと |
| --- | --- | --- | --- |
| | | | |

指定がない場合は30分を仮置きする。
過去の約束、現状と課題、次のアクション合意を優先する。

## 8. 顧客への質問
各テーマについて、次の情報を整理する。

- 質問する内容
- 質問する意図
- 想定される課題
- 回答によって変わる提案方針

## 9. 推奨施策
各施策について以下を記載する。

- 提案内容
- 提案の根拠
- 顧客にとっての価値
- 実施の前提条件
- 想定される懸念
- 優先順位

現契約で改善できる施策を優先する。
必要性が確認できた場合のみ追加支援を候補とする。

## 10. 今回合意したいこと
MTG終了時に決定したい事項を明記する。

- 何を実施するか
- 誰が担当するか
- いつまでに実施するか
- どの指標で成果を確認するか

## 11. 未確認事項と参照元
- 取得できなかったデータ
- 確認が必要な契約条件
- 検証が必要な仮説
- 使用したデータの参照元・日付

## 出力ルール
1. 重要な結論を先に記載する。
2. 事実・仮説・未確認事項を分ける。
3. 根拠のない数字や顧客発言を作らない。
4. 情報がなければ「未取得」と記載する。
5. アジェンダは最大3テーマにする。
6. 顧客の理想から逆算した提案にする。
7. CS担当者が実行できる具体的な内容にする。
8. 顧客情報を公開GitHubリポジトリへ書き込まない。
